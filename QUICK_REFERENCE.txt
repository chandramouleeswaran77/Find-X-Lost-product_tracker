                         KEY ENDPOINTS

Lost Items:
  GET    /api/lost                  - Get all lost items
  POST   /api/lost                  - Create lost item (with image)
  PUT    /api/lost/{id}             - Update lost item
  DELETE /api/lost/{id}             - Delete lost item
  PUT    /api/lost/{id}/resolve     - Mark as resolved

Found Items:
  GET    /api/found                 - Get all found items
  POST   /api/found                 - Create found item (with image)
  PUT    /api/found/{id}            - Update found item
  DELETE /api/found/{id}            - Delete found item
  PUT    /api/found/{id}/resolve    - Mark as claimed

Notifications:
  GET    /api/notifications/{userId} - Get user notifications
  PUT    /api/notifications/{id}/read - Mark as read

Messages:
  POST   /api/contact               - Send message (creates notification)

Admin:
  GET    /api/admin/statistics      - Get overall statistics
  GET    /api/admin/reports/monthly/pdf?year=2024&month=10 - Generate PDF

================================================================================
                         IMAGE DISPLAY
================================================================================

How It Works:
1. User uploads image in report form
2. Backend saves to: uploads/lost/ or uploads/found/
3. Backend stores full URL in MongoDB:
   "http://localhost:8080/uploads/lost/1234567890_image.jpg"
4. Frontend fetches and displays image everywhere

Verify Images:
- Check MongoDB: db.lost_items.findOne({}, { imageUrl: 1 })
- Should start with: http://localhost:8080/uploads/
- Test in browser: http://localhost:8080/uploads/lost/[filename]

Fix if Broken:
1. mkdir uploads\lost uploads\found
2. Restart backend
3. Upload new image
4. Check imageUrl in MongoDB

================================================================================
                         NOTIFICATION FLOW
================================================================================

Match Notifications (Both Users):
1. User A reports lost: "AirPods Pro"
2. User B reports found: "AirPods"
3. Keywords match: "airpods"
4. Both users get notification
5. Email sent to both (if configured)
6. Status: "POSSIBLE_MATCH"

Message Notifications (Item Owner):
1. User B views User A's item
2. User B clicks "Send Message"
3. Sends message
4. User A gets notification in bell icon
5. User A gets email (if configured)

                         EMAIL SETUP (OPTIONAL)
================================================================================

Gmail Quick Setup:
1. Enable 2FA: https://myaccount.google.com/security
2. Generate App Password: Security → App passwords → Mail → Generate
3. Copy 16-character password: xxxx xxxx xxxx xxxx

4. Add to backend/src/main/resources/application.properties:
   spring.mail.host=smtp.gmail.com
   spring.mail.port=587
   spring.mail.username=your-email@gmail.com
   spring.mail.password=xxxx xxxx xxxx xxxx
   spring.mail.properties.mail.smtp.auth=true
   spring.mail.properties.mail.smtp.starttls.enable=true

5. Restart backend
6. Test by creating matching items

Note: Email is OPTIONAL. In-app notifications work without it!

================================================================================
                         TROUBLESHOOTING
================================================================================

Images Not Showing:
  - mkdir uploads\lost uploads\found
  - Restart backend
  - Check imageUrl in MongoDB starts with http://localhost:8080
  - Upload new image

No Notifications:
  - Click bell icon to refresh
  - Check MongoDB: db.notifications.find()
  - Verify matching keywords in items
  - Check backend console logs

Email Not Sent:
  - Email is optional (in-app notifications work without it)
  - Configure SMTP if you want emails
  - Check spam folder
  - Use App Password for Gmail (not regular password)

Admin Not Working:
  - Set role in MongoDB: { role: "ADMIN" }
  - Logout and login again
  - Navigate to /admin directly

Build Errors:
  - cd backend
  - .\mvnw.cmd clean install
  - Check for red error messages
